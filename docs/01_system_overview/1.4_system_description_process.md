**1.4 Library System Process Description**

**1.4.1 Material Management Process**
Objective: To establish identification information for new materials (books, publications, journals), ensuring uniqueness and determining storage locations to facilitate research and automated borrowing/returning operations.
Actors: Staff, System.
Implementation Steps:
-	Step 1: Receive and input material information: The Staff enters material details into the system, including: Title, Author, Publisher, Publication Year, Genre, and Book ID.
-	Step 2: Validate and check for duplicates: The system checks key identifiers (Title, Book ID, Author). If mandatory fields are missing, the system issues a prompt requesting the missing information to ensure data accuracy and completeness. Simultaneously, the system automatically checks the ID book or title against the database to prevent the entry of duplicate titles.
-	Step 3: Assign unique code and generate barcode: Once the material information is validated, the system automatically generates a unique ID for each specific physical copy. The system supports the creation and printing of barcode labels (Barcode/QR Code) for physical application, enabling future identification via scanning devices.
-	Step 4: Update storage location and inventory quantity: The Staff classifies and assigns the item to a physical location (Reading Room, shelf number, tier number). The system updates the initial inventory quantity in the database.
-	Step 5: Confirm storage status and update: The system records the information in the database and issues a "Material added successfully" notification. The official record is set to "Available" status, allowing readers to study the material and borrow it.

**1.4.2 Account Registration and Card Issuance**
Objective: To establish identity, grant access rights, and manage the reader account lifecycle within the system.
Actors: Reader, Staff, System
Implementation steps:
-	Step 1: Information collection: The reader provides core information, including: full name, date of birth, gender, Citizen ID/National ID number, phone number, address, and email (used as the username).
-	Step 2: Duplicate check and validation: The system automatically checks the phone number, email, or Citizen ID against the database to prevent account duplication. It also verifies the completeness of the required core information.
-	Step 3: Account creation and security:
o	The system assigns a unique Reader ID.
o	A default password is set and encrypted before storage to ensure information security.
-	Step 4: Card issuance and account activation: The system issues a library card (physical card or in-app QR code). The account status is set to "Active," allowing the reader to begin searching for and borrowing books.
-	Step 5: Status and card validity management:
o	Activation status (Active): The reader has full borrowing/returning privileges and access to all online services.
o	Temporary lock status (Locked): Reason: The reader has violated regulations or the card has been reported lost. The system blocks borrowing and login privileges until a staff manually unlocks the account after resolving the violation. 

o	Card validity rules:
•	Automatic card scanning: The system runs background processes (agents) to check card expiration dates.
•	Expiration notifications: 5–7 days before a card expires, the system automatically sends an email, SMS, or app notification to remind the patron.
•	Enforcement of limits: When a patron renews their membership (if applicable), the system updates the status at the end of the day, automatically switching the card status from "Expired" back to "Valid."

**1.4.3 Search and reservation process**
Objective: To enable patrons to search for desired materials, view detailed information, and reserve books before visiting the library, ensuring availability.
Actors: Patron (Member), System
Implementation steps:
-	Step 1: Enter keywords and perform a search:
o	Enter search terms (book title, author, genre, or Book ID) into the search bar.
o	Utilize advanced system filters, such as searching by language or publication year.
-	Step 2: Display and sort search results:
o	The system lists matching titles, including illustrations and current status (Available/Checked out).
o	Patrons can sort the list by most borrowed, newest arrival, or alphabetical order.
-	Step 3: View detailed material information:
o	Upon selecting a specific item, the system displays full details: summary, bibliographic information, publication date, location, and review history from other patrons.
o	The system displays the number of copies remaining on the shelf available for borrowing.
- Step 4: Managing the list:
o	Readers select the “Add to loan list” function to save books of interest.
o	The system allows users to review this list (viewing dates and current quantities), update quantities, or remove items before proceeding to the next step.
-	Step 5: Scheduling an appointment and reserving books:
o	The system retrieves the event's scheduled time.
o	The system performs a validation check (verifying account validity and checking for overdue fines). If valid, the system executes a “temporary book hold” on the shelf for a specific period. ...specific timeframe.
-	Step 6: Confirmation and notification: The system sends a successful reservation confirmation via email or the app, including a QR code for the reader to present to the staff when collecting the book. The book's status in the database changes from "Available" to "Reserved."

**1.4.4	Book borrowing process**
Objective: To record the issuance of materials, establish the reader's responsibility for safekeeping, and automatically set the return deadline.
Actors: Reader (borrower/member), Staff, System
Implementation steps:
-	Step 1: Reader authentication: The reader presents their library card (physical card or QR code). The staff scans the code to retrieve the reader's information. The system checks the account status in the database; the account must be "Active," valid (not expired), and not on the list of violators.
-	Step 2: Check limits and constraints: The system automatically checks the number of books the reader currently holds. If the total of the books to be borrowed plus those currently held exceeds the prescribed limit, the system will reject the transaction.
-	Step 3: Scan item identifier: The staff uses a scanner to read the barcode of each book selected by the reader. The system verifies the book's status in the inventory: the book must be "Available" or previously "Reserved" by that specific reader. If the book is currently "On Loan" or under "Maintenance," the system will report an error.
-	Step 4: Create loan record and set deadline: The staff confirms the loan. The system executes a transaction to ensure data integrity:
o	Creates a loan record containing: Reader ID, Book ID, and Loan Date (defaulting to the current date).
o	Automatically calculates the Due Date based on library policy (14 days from the loan date).
o	Updates the book status from "Available" to "On Loan."
-	Step 5: Confirmation and slip printing: The system prints a loan slip (or sends a notification via Email/App) to the reader. The transaction concludes, and the information is stored in the system log for future lookup and statistical analysis.

**1.4.5 Renewal process**
Objective: To allow readers to extend the loan period for materials without physically bringing the books to the library (in the case of online renewal), thereby optimizing the user experience and reducing the rate of overdue books.
Actors: Reader, Staff, System.
Implementation steps:
Scenario 1: Online renewal (via App):
-	Step 1: Login and access: The reader logs into their personal account and accesses the "List of borrowed materials" section.
-	Step 2: Material selection: The system displays the list of currently held materials along with their current due dates. The reader selects the "Renew" function for the desired material.
-	Step 3: Automated condition check: The system performs the following checks:
o	The book is not currently "Reserved" by another reader.
o	The reader's account is not locked, and there are no other overdue books.
o	o	The number of renewals has not exceeded the allowed limit (maximum of 4 times per title). -	Step 4: Update new due date: If valid, the system updates the record with a new due date following the previous one. The loan slip status is updated to "Renewed."
-	Step 5: Confirmation and notification: The system sends a notification confirming the successful renewal and displays the new due date on the interface.
Scenario 2: Renewal at the counter (via Staff):
-	Step 1: Authentication: The patron presents their library card or the book code. The staff scans the code to retrieve loan record information.
-	Step 2: Physical inspection: The staff checks the physical condition of the book (if brought in) and reviews system constraints, similar to the online renewal process.
-	Step 3: Processing renewal: The staff confirms the action in the management software. The system records the transaction and prints a renewal receipt.

**1.4.6	Book return, violation handling, and payment process.**
Objective: To return materials to the stacks, verify their condition, handle non-compliant issues (overdue returns, damage), and collect fines to ensure fairness.
Actors: Patron, Staff, System
Implementation steps:
-	Step 1: Receipt and scanning of material code: The patron presents the book to be returned, and the staff scans the barcode on the book. The system automatically retrieves the corresponding loan record (Patron ID, Loan Date, Due Date) from the circulation database.
-	Step 2: Checking due date and physical condition: The system automatically compares the actual return date with the "Due Date." If the actual return date is later than the due date, the system assigns the status "Late Return." Regarding integrity verification, the staff physically inspects the book's condition (checking for tears, missing pages, or soiling). If issues are found, the staff updates the system with the extent of the damage. 
-	Step 3: Generate Penalty Slip (if a violation occurs): If a violation is detected (late return, damage, or loss), the system automatically calculates the penalty amount based on business rules. It creates a penalty invoice record containing the reason for the penalty, the amount, the creation date, and the status "Pending Payment."
-	Step 4: Process payment: The patron pays the penalty at the counter via cash or bank transfer. The staff confirms the payment in the software; the system updates the invoice status to "Paid" and prints a receipt for the returned item and the penalty fee.
-	Step 5: Update status Inventory and Account: Final transaction processing:
•	Update item status from "On Loan" to "Available."
•	Remove the loan record from the patron's active loans list.
•	In cases of serious violations, the system may change the patron's account status to "Temporarily Suspended" pending resolution.

**1.4.7	Statistics and Reporting Process**
Objective: Automatically aggregate data from book circulation and patron management activities to provide a comprehensive overview, supporting staffs and administrators in making accurate decisions regarding resource allocation.
Actors: Staff, Administrator (Admin), System.
Implementation steps:
-	Step 1: Automated data collection: The system automatically scans and aggregates data from all operational modules, including: patron information, book catalog, borrowing/return history, and violation/fine records.
-	Step 2: Processing and KPI calculation: The system calculates key metrics:
•	Ratio of books currently in circulation to total inventory.
•	Borrowing frequency by specific book title or genre.
•	Rate of overdue returns and total fines collected.
-	Step 3: Report and Dashboard generation: The system provides two data display formats:
•	Periodic reports: Automatically generated reports (daily/weekly/monthly/yearly).
•	Visual Dashboard (Real-time): Charts displaying borrowing trends or new patron numbers in real-time.
-	Step 4: Trend analysis and alerts: Based on processed data, the system performs analysis to:
•	o	Identify high-demand ("hot") titles facing shortages and recommend restocking. o	Flag damaged items requiring disposal or maintenance.
•	Identify groups of patrons with frequent policy violations for appropriate action.
-	Step 5: Report generation and sharing permissions: Enable data export to formats such as PDF, Excel, or CSV for archiving or formal approval. The system supports automated email reporting to managers based on a set schedule. It also manages report viewing permissions: staffs can only view daily circulation reports (loans and returns), whereas managers can access financial and staff performance reports.
