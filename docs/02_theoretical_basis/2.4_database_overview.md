# 2.4 Overview CSDL
**2.4.1 Concept of the management process**

Catalogue Management

•	Books: Store information for each book (Book ID, Title, Summary, Publication Year, Stock Quantity, Status).

•	Authors: Manage author information (Author ID, Author Name, Biography).

•	Categories: Classify books for easy lookup (Category code, Category name).

•	Publishers: Information regarding the printing and publishing entity.

Reader Management

•	Reader: Store borrower information (Reader ID, Full name, Date of birth, Address, Email, Library card expiration date).

Circulation Management

•	Borrow_Records: Record the overview information for each transaction (transaction ID, Reader ID, loan date, expected return date, and staff ID).

•	Borrow_Details: Decompose the LoanRecord table to manage multiple books within a single loan transaction (Loan Slip ID, Book ID, book status at time of borrowing/return, actual return date, and fines for overdue returns or damage).

Staff Management

•	Staff: Manage information on librarians or internal system users (Employee ID, Name, Position, Login account, Admin).

**2.4.2 Core functions of a database management system**

A complete database management system must comprehensively meet the functional groups of management, operation and data protection. These core functions are specified in the table below:

| Functional group | Technical components | Detailed description |
|----|-----|-----|
| Data definition | language DDL | Provides CREATE, ALTER, and DROP syntax to create, modify, and define the structure of data objects (tables, views, indexes). |
| Data manipulation | language DML | INSERT, UPDATE, DELETE and query (SELECT) to process and retrieve data. |
| Access Control and Security | language DCL | Implement access controls (GRANT, REVOKE), account management, and encryption to protect the system against unauthorized access. |
| Ensure Data Integrity | System constraint | Apply business rules (constraints, triggers, checks) to maintain data accuracy and consistency. |
| Backup and restore | Unility tools | Provides automatic and manual mechanisms for data backup and recovery in the event of hardware or software failures. |
| Simultaneous control | control mechanism | Manage sessions and synchronize multi-user access to prevent conflicts and ensure consistency during read and write operations. |

**2.4.3 The role of databases in software architecture**

A Database Management System (DBMS) plays a pivotal role at the core of technology architecture thanks to its five core characteristics:

•	Centralization: Centralizes all business data resources into a single unified infrastructure, eliminating data fragmentation and minimizing redundant data duplication.

•	Data Consistency: Ensures data across all modules remains fully synchronized and accurate through strict constraint systems and automated business rules.

•	Data Independence: Completely decouples physical storage structures underneath from the application logic above. Consequently, upgrading hardware or altering table structures does not disrupt or impact the application codebase.

•	Advanced Security and Safety: Enforces multi-tiered access control—from database level down to table, row, or specific column level—effectively preventing data breach threats.

•	Performance Optimization: Utilizes intelligent query optimization algorithms combined with indexing mechanisms and caching to process massive volumes of records in minimal response times.
